# 身份证识别脚本需求清单

## 1. 文档信息

- 文档版本：V1.0
- 产品形态：跨平台 Python 命令行脚本
- 处理方式：本地离线批量识别
- 输出格式：Excel（`.xlsx`）

## 2. 建设目标

提供一个可在 Windows、macOS 和 Linux 上运行的 Python 命令行脚本。脚本递归扫描指定目录中的身份证正面图片，在本机完成 OCR 识别和身份证号校验，并将姓名、完整身份证号及处理状态导出到 Excel，方便批量整理和人工复核。

## 3. 用户与使用场景

- 目标用户：需要批量整理身份证正面图片信息的业务人员或技术人员。
- 典型场景：用户将不同子目录中的身份证正面图片集中放入一个根目录，执行一次命令后获得统一的 Excel 结果。
- 使用前提：用户有权处理图片中的个人信息，并负责妥善保管原始图片和导出文件。

## 4. 范围

### 4.1 首版范围

- 通过命令行指定输入目录和 Excel 输出路径。
- 默认递归处理输入目录及所有子目录。
- 识别身份证正面的姓名和18位身份证号。
- 对识别结果进行格式、出生日期和校验码检查。
- 记录成功、失败和重复三类处理结果。
- 在本机离线生成 `.xlsx` 文件。

### 4.2 首版不包含

- 身份证反面信息识别。
- PDF、视频、摄像头实时画面或压缩包输入。
- 桌面图形界面、Web 页面或移动端应用。
- 云 OCR、第三方在线接口或识别数据上传。
- 人工补录、图片编辑、身份证真伪鉴定或人脸比对。

## 5. 功能需求

### 5.1 命令行接口

命令格式：

```shell
python id_card_ocr.py --input <目录> --output <文件.xlsx> [--overwrite]
```

参数规则：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--input` | 是 | 待处理图片的根目录 |
| `--output` | 是 | 输出 Excel 文件路径，扩展名必须为 `.xlsx` |
| `--overwrite` | 否 | 允许覆盖已存在的输出文件；未提供时禁止覆盖 |

退出码：

| 退出码 | 含义 |
| --- | --- |
| `0` | 所有受支持图片均识别成功，且没有重复记录 |
| `1` | 输入、初始化、参数或导出等致命错误 |
| `2` | 已生成 Excel，但至少存在一条识别失败或重复记录 |

### 5.2 输入目录与文件扫描

- 输入目录必须存在、可读且为目录，否则输出明确错误并返回退出码 `1`。
- 默认递归扫描输入目录及所有子目录。
- 支持 JPG、JPEG、PNG 图片，文件扩展名不区分大小写。
- 不支持的文件应跳过，不纳入处理总数，也不作为识别失败记录。
- 扫描结果按相对路径稳定排序后依次处理，确保多次运行的顺序一致。
- 输入目录中没有任何受支持图片时，应输出明确错误、返回退出码 `1`，且不生成 Excel。
- 每张受支持图片必须最终归入成功、失败或重复之一，不允许静默遗漏。

### 5.3 本地 OCR 与字段提取

- 图片解码、预处理和 OCR 必须全部在本机执行，不允许调用云服务或第三方在线接口。
- 每张图片只提取身份证正面的“姓名”和“公民身份号码”。
- 身份证号必须按18位结果处理，末位小写 `x` 统一转换为大写 `X`。
- 姓名和身份证号均成功提取且校验通过时，记录为识别成功。
- 姓名或身份证号任一缺失、图片无法读取、OCR 无有效结果或身份证号校验失败时，记录为识别失败。
- 识别失败时不得输出未经校验的猜测姓名或身份证号。
- 单张图片处理失败不得中断其他图片的处理。

### 5.4 身份证号校验

- 身份证号必须为18位，前17位为数字，末位为数字或大写 `X`。
- 身份证号中的出生日期必须是合法日期。
- 身份证号必须通过国家标准的18位身份证校验码规则。
- 任一校验未通过时，该图片按识别失败处理，状态中记录不含完整敏感数据的原因。

### 5.5 重复数据处理

- 以校验通过后的完整身份证号作为唯一键去重。
- 相同身份证号首次出现时保留正常结果。
- 后续重复图片仍在 Excel 中保留来源文件记录，但姓名和身份证号留空。
- 重复行的识别状态写明“重复，已保留：`<首次来源文件>`”。
- 只要存在重复记录，本次运行返回退出码 `2`。

### 5.6 Excel 导出

- 输出文件必须为 `.xlsx` 格式。
- 工作表名称固定为“识别结果”。
- 第一行固定为表头，列顺序如下：

| 列序号 | 列名 | 内容规则 |
| --- | --- | --- |
| 1 | 来源文件 | 相对于输入根目录的文件路径 |
| 2 | 姓名 | 成功时填写完整姓名，失败或重复时留空 |
| 3 | 身份证号 | 成功时填写完整号码，失败或重复时留空 |
| 4 | 识别状态 | 成功、失败原因或重复说明 |

- 身份证号单元格必须以文本格式写入，禁止以数值或科学计数法保存。
- 识别失败行必须保留来源文件，姓名和身份证号留空，并在识别状态中给出可操作的失败原因。
- Excel 行顺序必须与稳定排序后的图片处理顺序一致。
- 输出文件已存在且未提供 `--overwrite` 时，拒绝覆盖、返回退出码 `1`，且不得修改原文件。
- 导出时先写入同目录临时文件，完整写入成功后再原子替换目标文件，避免留下不完整结果。
- 临时文件无论成功或失败均应清理。

### 5.7 运行反馈

- 处理期间应提供不含个人敏感信息的进度或数量反馈。
- 完成后应汇总扫描数、成功数、失败数、重复数和输出文件路径。
- 终端及日志不得打印完整姓名、身份证号或 OCR 原始文本。
- 致命错误应说明错误类型和处理建议，但不得泄露个人敏感信息。

## 6. 非功能需求

### 6.1 兼容性

- 支持 Windows、macOS 和 Linux。
- 文件路径处理不得依赖单一操作系统的路径分隔符。
- 中文文件名、目录名、姓名和 Excel 内容不得出现乱码。

### 6.2 隐私与安全

- 脚本运行期间不得主动建立网络连接。
- 不复制、缓存或长期保存原始身份证图片。
- 除指定 Excel 外，不得在其他持久化文件中保存姓名、身份证号或 OCR 原始结果。
- 异常信息、进度输出和临时文件名不得包含完整身份证号。
- 导出的 Excel 包含完整身份证号，使用者必须负责文件访问控制、传输和销毁。

### 6.3 稳定性与数据完整性

- 单个文件异常不得导致整个批次中断。
- 任何可处理图片都必须有明确结果，不允许静默丢失。
- 导出失败时不得破坏已存在的目标文件。
- 处理结果计数必须满足：扫描数等于成功数、失败数和重复数之和。

### 6.4 识别质量

- 验收样本由双方确认，至少包含100张字段清晰、无遮挡、无严重反光的身份证正面图片。
- 在验收样本中，姓名和身份证号同时完全正确的图片比例不得低于95%。
- 准确率按“姓名与身份证号均完全匹配”的图片数除以验收图片总数计算，不按单字段拆分。
- 无法可靠识别的图片应进入失败记录，不得用猜测值换取表面成功率。

| AC-06 | 图片中的姓名和身份证号正确且校验通过 | Excel 成功行包含来源文件、完整姓名、文本格式完整身份证号和成功状态 |
| AC-07 | 身份证号末位被识别为小写 `x` | 输出统一为大写 `X` |
| AC-08 | 图片损坏、字段缺失或身份证号校验失败 | Excel 保留来源文件，姓名和号码留空，状态写明原因 |
| AC-09 | 一个批次中某张图片失败 | 其他图片继续处理，最终退出码为 `2` |
| AC-10 | 两张图片识别出同一身份证号 | 首条保留，后续行字段留空并指明首次来源，最终退出码为 `2` |
| AC-11 | 输出文件已存在但没有 `--overwrite` | 原文件不变，不生成替代文件，退出码为 `1` |
| AC-12 | 输出文件已存在且提供 `--overwrite` | 完整生成后原子替换目标文件 |
| AC-13 | 全部图片识别成功且无重复 | 生成 Excel，退出码为 `0` |
| AC-14 | 检查终端输出、日志和临时文件 | 不出现完整姓名、身份证号或遗留敏感数据 |
| AC-15 | 在至少100张约定清晰样本上验收 | 姓名和号码同时完全正确的比例不低于95% |
| AC-16 | 核对处理汇总与 Excel | 扫描数等于成功数、失败数与重复数之和，每张图片均可追溯 |
